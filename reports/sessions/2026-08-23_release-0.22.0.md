# 2026-08-23 — release 0.22.0

## What was asked

Update the release notes and the version number to 0.22.

## What was found

There were **no release notes to update**. Upstream's lived in
`doc/source/release_notes.rst`, which went when `doc/` was dropped, and
`pyproject.toml`'s `Changelog` URL pointed at `reports/DECISIONS.md` as a
stand-in. So `CHANGELOG.md` was written from the fork's commit history, and the
URL now points at it. Versions before 0.22.0 are upstream's and the file says so
rather than restating them.

## What changed

- `optbinning/_version.py` → `0.22.0`. It is the single source; `pyproject.toml`
  reads it through `tool.setuptools.dynamic`.
- `CHANGELOG.md`, new, with the 0.22.0 section: requirements, packaging,
  the LocalSolver removal, what was added, what was fixed, testing, and the one
  known issue.
- `MANIFEST.in` ships it in the sdist.
- README: the two sample outputs printed `Version 0.21.0`; the badges said 176
  tests and 85% coverage; the testing table and the per-subsystem coverage table
  were a release out of date. All re-measured, not carried forward.

## One claim that had gone false

The README said **"No feature has been removed."** That stopped being true when
`solver="ls"` went. It now says no *subsystem* has been removed, names the
exception, and the change table has a LocalSolver row. Worth noting as the kind
of claim that ages silently: nothing failed, and no test could have caught it.

## Numbers, re-measured for the release

212 passed, 0 failed on Python 3.13.15; 11,301 statements, 1,244 uncovered,
**89%**; flake8 gate 0. `binning/mdlp.py` and `binning/distributed/plots.py`,
both largely untested upstream, are now at 100%.

At the time of writing this work was on branch `release-0.22` and nothing had
been merged, and the release had not been tagged or uploaded.
